# Архитектура прошивки

Ничего из описанного не запускалось на настоящей плате. Слои, которые можно
проверить без железа, вынесены в заголовки и покрыты хост-тестами: алгоритмы
(`test_core`), жизненный цикл записи (`test_session`) и пропадание питания с
долгой эксплуатацией (`test_faults`). Запуск `bash tools/host_tests.sh`,
с `--sanitize` — под ASan и UBSan.

## Две платы, одна прошивка

Профиль платы выбирается при сборке (`BoardConfig.h`), логика записи о нём не
знает: формат звука приходит в `session::Writer` значением, пины живут только в
`XiaoVoiceRecorder.ino` и `Feedback.ino`.

| | `sense` (по умолчанию) | `reva` (`-DRECORDER_BOARD_REVA`) |
| --- | --- | --- |
| Плата | XIAO ESP32-S3 Sense | Recorder PCB V1 RevA, `docs/hardware/recorder-pcb-v1-reva.md` |
| Микрофон | встроенный PDM Sense | 2 × IM72D128V, общие CLK/DATA, слоты L/R |
| PDM CLK / DATA | GPIO42 / GPIO41 | GPIO5 / GPIO6 |
| Формат | 16 кГц / 16 бит / **моно**, 32 000 Б/с | 16 кГц / 16 бит / **стерео**, 64 000 Б/с |
| Часть 10 минут | 19 200 000 байт | 38 400 000 байт |
| Кольцо предзаписи 30 с | 1 МиБ = 32,8 с | 2 МиБ = 32,8 с |
| microSD SPI | GPIO7/8/9, CS GPIO21 | GPIO7/8/9, CS GPIO44 |
| Кнопка REC | GPIO0 (BOOT) | GPIO2 |
| Батарея | нет, `Batt: unknown` | ADC GPIO1 через делитель |
| Вибро / LED | проводами: GPIO3 (ключ) / RGB GPIO4, 5, 6 | GPIO3 (затвор MOSFET) / GPIO4 |
| Сборка | `bash tools/build.sh` | `bash tools/build.sh --board reva` |
| Проверено на железе | нет | нет, платы ещё нет |

Оба профиля собираются `tools/build.sh` (перед пушем — sense). Sense работает на плате; RevA —
статическая сборка вперёд, чтобы стерео-арифметика и пины были готовы к
приезду PCB, а не писались в день приезда.

## Поток звука

```text
PDM microphone(s)   Sense: GPIO42 CLK / GPIO41 DATA, моно
                    RevA:  GPIO5  CLK / GPIO6  DATA, два слота L/R
        |
        v
    ESP_I2S PDM RX, 16 kHz / 16-bit / board::AUDIO.channels
        |
        v
  задача captureTask (FreeRTOS, ядро 1, приоритет выше loop)
        |
        v
  RingBuffer в PSRAM, 30 с звука  <-- единственный писатель
        |
        | pop() из loop(), только в RECORDING
        v
   FAT32 microSD, куски по 8 КиБ
        |
        v
   REC0007_P01.WAV (.TMP пока открыт, .BAD при сбое, _R после восстановления)
```

Разделение сделано ради одного: чтение DMA микрофона не должно ждать ни SD, ни
TLS, ни кнопку. Всё остальное — кооперативно в `loop()`.

Приоритет: **RECORDING > SD WRITE > BUTTON > UPLOAD**.

### Кадры, не сэмплы

Кадр (frame) — один отсчёт по всем каналам: 2 байта в моно, 4 в стерео. Все
счётчики (`captured_frames`, `written_frames`, `dropped_frames`,
`expected_by_clock`) считают кадры, поэтому `dropped_frames = 0` значит одно и
то же на любой плате. Обрезка до целых кадров (`Format::wholeFrames`) идёт
везде, где байты попадают на карту или в заголовок.

## Состояния

```text
        питание
           |
           v
   [ FAULT ] <----- нет карты / нет микрофона
           |
           v
   [ ARMED ] микрофон слушает, SD молчит, буфер копит последние ~30 с
       |  ^
 короткое|  | длинное нажатие (2 с): закрыть часть, создать .END, отправить
 нажатие |  |
       v  |
   [ RECORDING ] буфер сливается на карту, части по 10 минут
       |
 короткое нажатие -> ★ метка в REC0007_Pnn.MRK (append + flush)
```

Запись физически начинается за ~30 секунд ДО нажатия: при START буфер не
очищается, а становится началом первой части.

## Границы частей

Часть заканчивается ровно на `Format::partMaxBytes()` (10 минут в байтах
своего формата), а не по часам. Стык не теряет ни одного кадра, и смещение
метки считается арифметикой от позиции в сессии в секундах — одинаково для
моно и стерео (`AudioFormat.h`, `Writer::markAt`).

## Заголовок WAV и восстановление

Заголовок строится из формата, которым писалась часть: каналы, частота, byte
rate, block align. Восстановление после пропадания питания читает формат из
заголовка самого `.TMP`, а не из собранного профиля: карта из моно-прототипа
чинится и в стерео-прошивке, каждая часть — по своему размеру кадра.

| --- | --- | --- |

| `Uploader.ino` | кооперативная отправка по HTTPS, очередь на карте, `X-Battery`/`X-Firmware` | нет |

| `Storage.h` | интерфейс хранилища, через который Session.h видит карту | — |
| `RingBuffer.h` | кольцевой буфер без блокировок | **да** |
| `Button.h` | короткое/длинное нажатие, антидребезг | **да** |

| `Battery.h` | напряжение через делитель, процент по кривой Li-Po | **да** |
| `UploadPolicy.h` | классы ответов, backoff, имена файлов, X-Marks | **да** |
| `Types.h` | типы из сигнатур (Arduino собирает .ino в один файл) | — |

Жизненный цикл записи вынесен за интерфейс `Storage` намеренно: закрытие
части, `.END`, восстановление и очистка — самый опасный код прошивки, и
именно он проверяется на хосте с хранилищем в памяти и отказами по заказу
(не переименовался, запись оборвалась, файл не открылся). Две ошибки, которые
нашлись при внешнем разборе 15 сентября 2026 — `.END` после неудачного
закрытия и потеря меток у восстановленной части, — теперь ловятся тестами.

## Кнопка

Фронты снимает прерывание (`buttonIsr`), дребезг гасится там же по времени.
Цикл разбирает очередь фронтов с их настоящими отметками времени, затем
опрашивает уровень. Иначе короткое нажатие, целиком попавшее в окно
TLS-рукопожатия, не было бы замечено вовсе.

Вместе с фронтом прерывание запоминает положение звукового потока
(`RingBuffer::head()` — обычная атомарная загрузка). Метка ставится по нему, а
не по моменту, когда цикл добрался до события: иначе задержка на рукопожатии
сдвинула бы ★ на те же секунду-две.

## Предел частей

99 частей — это 16,5 часа. При достижении предела сессия закрывается чисто
(`.END` на месте), и тут же начинается следующая: буфер не очищается, поэтому
его содержимое становится предзаписью новой сессии. Звук на стыке не теряется.

## Отправка

Машина состояний `UP_IDLE -> UP_WIFI -> UP_CRC -> UP_CONNECT -> UP_PROBE ->
UP_SEND -> UP_REPLY -> UP_CLOSE`. Каждый вызов `serviceUpload()` делает один
ограниченный шаг и уступает `loop()` между блоками по 4 КиБ, если ждёт нажатие
или кончился бюджет (25 мс, в записи 10 мс). START обрывает передачу
(`preemptUpload`); следующая попытка спрашивает у сервера, сколько байт уже
дошло (`UP_PROBE`), и докачивает хвост.

CRC части, закрытой с момента загрузки, считает `session::Writer` по мере
записи (`Crc32.h`, `knownCrc`), и `UP_CRC` проходит сразу. После перезагрузки,
у восстановленных `_R`-частей и после ответа 422 сумма считается чтением всего
файла кусками — шаг возвращает три состояния, и оборванное чтение уводит часть
в обычный повтор по расписанию.

Блокирующими остаются отдельные вызовы: DNS + TCP + TLS (замер 12 окт: около
2,2 с), чтение карты и запись в сокет. Поэтому кнопка читается прерыванием, а
фронты ждут в очереди. Скорость тела упирается в буфер отправки TCP: у Arduino
он 5744 байта (81 КиБ/с), IDF-сборка с 32 КиБ дала 436 КиБ/с.

С каждой частью уходит `X-Firmware: 0.4.0+<профиль>`; `X-Battery` — только с
платы, которая умеет измерить заряд (RevA). На Sense заголовка нет, и сервер
честно показывает «диктофон не сообщал».

Флаг `UPLOAD_DURING_RECORDING` (по умолчанию выключен) разрешает отдавать
закрытые части, пока пишется следующая. Включать только после измерения
`dropped_frames` под нагрузкой на настоящей плате.

## Батарея

`readBattery()` возвращает `battery::Status{supported, millivolts, percent}`.
На Sense `supported = false`, и это правда о плате, а не заглушка: штатная
XIAO не даёт прошивке ни делителя, ни газометра. На RevA — 16 чтений
`analogReadMilliVolts` с GPIO1, умноженные на коэффициент делителя
(`board::BAT_DIVIDER`, подтвердить по схеме), и процент по кусочно-линейной
кривой Li-Po. Чтение не вызывается во время записи.

## Путь к ESP-IDF

Каталог `firmware/` собирает тот же код через `idf.py` с Arduino 3.3.12 как
компонентом ESP-IDF 5.5.5 (`bash tools/idf.sh build`) — основная прошивка
платы с 12 окт 2026. Arduino-сборка (3.3.11) остаётся для быстрой проверки и отката.
Порядок замены подсистем (звук первым, ради двух слотов PDM на RevA) — в
`firmware/README_RU.md`.

## Резервируемые ресурсы

Sense: GPIO41/42 микрофон, GPIO7/8/9 SPI карты, GPIO21 CS (общий с
пользовательским LED), GPIO0 кнопка BOOT как REC. LED R/G/B на GPIO4/5/6 и
вибро на GPIO3 — по умолчанию из `BoardConfig.h`, перекрываются через Serial
(`led_pin`, `led_g_pin`, `led_b_pin`, `vibro_pin`). Цвет — `Indicator.h`.

RevA: GPIO5/6 микрофоны, GPIO7/8/9/44 карта, GPIO2 кнопка, GPIO1 АЦП батареи,
GPIO3 вибро, GPIO4 LED. Занятые пины прошивка отдать под LED/вибро не даст.

Камера в проекте не используется.
