# XIAO ESP32-S3 Sense Voice Recorder — прошивка v0.3

Программный прототип носимого диктофона на **Seeed Studio XIAO ESP32-S3 Sense**.

**Ни одна строка этой прошивки не исполнялась на настоящей плате.** Плата в
пути, ожидается 2 октября 2026. Всё ниже — то, что написано, собирается и,
где возможно, проверено алгоритмически. Не то, что измерено.

Три степени готовности, и они здесь не для красоты:

| Значок | Что означает |
| :-: | --- |
| ✅ | проверено автотестом на обычном компьютере |
| ⚠️ | написано и собирается, на железе не проверялось |
| ⏳ | запланировано |

## Что делает диктофон

Одна кнопка, три жеста.

| Жест | Состояние | Что происходит |
| --- | --- | --- |
| Короткое нажатие | ARMED | START: запись начинается, **включая последние ~30 секунд до нажатия** |
| Короткое нажатие | RECORDING | ★ метка важного момента |
| Длинное, 2 секунды | RECORDING | STOP: часть закрывается, включается отправка |

После включения устройство само переходит в ARMED: микрофон слушает
постоянно, а на карту ничего не пишется. Звук течёт в кольцевой буфер в PSRAM
на 1 МиБ — это 32,8 секунды. При старте записи буфер не очищается, а
становится началом первой части.

Ради этого всё и затевалось: разговор, который стал важным только сейчас,
сохраняется с того места, где он ещё не был важным.

## Проверки без платы

```bash
bash tools/host_tests.sh            # нужен g++
bash tools/host_tests.sh --sanitize # то же под ASan и UBSan
bash tools/host_tests.sh --remote   # если g++ нет: сборка и прогон на VPS
```

2109 проверок в трёх наборах.

* `test_core` — алгоритмы: кольцевой буфер, кнопка, арифметика частей, правила
  отправки.
* `test_session` — жизненный цикл записи поверх хранилища в памяти с отказами
  по заказу: файл не переименовался, запись оборвалась, заголовок не
  перезаписался, файл не удаляется.
* `test_faults` — пропадание питания в каждый опасный момент (после создания
  части, посреди записи, на стыке частей, после части но до `.END`, посреди
  метки, во время очистки), повторное восстановление, 500 сессий подряд,
  заполненная карта, исчерпание номеров сессий, точность метки.

У всего набора `test_faults` одно утверждение: **ни один байт, уже дошедший до
карты, не теряется**. Что не успело дойти — потеряно по определению, питания
не было.

Тесты идут и под ASan с UBSan: выход за границы массива, использование
освобождённой памяти, утечки и неопределённое поведение в C++ не видны ни
глазами, ни обычными проверками.

Это проверка логики, а не железа: ни микрофона, ни карты, ни сети в них нет и
быть не может. Ровно поэтому логика вынесена в заголовки — `RingBuffer.h`,
`Button.h`, `PartMath.h`, `UploadPolicy.h`, `Session.h`, — а всё, что трогает
железо, живёт в `.ino` и `SdStorage.h`.

Те же проверки, сборка прошивки под ESP32-S3, тесты сервера с настоящим ffmpeg
и сборка фронтенда идут в GitHub Actions на каждый push:
`.github/workflows/ci.yml`.

Сборка прошивки:

```bash
bash tools/build.sh
```

## Файлы на карте

| Имя | Что значит | Удаляется автоматически |
| --- | --- | --- |
| `REC0007_P01.TMP` | часть пишется либо не закрыта после пропадания питания | нет |
| `REC0007_P01.WAV` | закрытая часть, ждёт отправки | нет |
| `REC0007_P01.MRK` | метки этой части, по секунде на строку | вместе со своей `.SENT` |
| `REC0007_N08.END` | сессия 7 закрыта чисто, в ней 8 частей | нет |
| `REC0007_P01.SENT` | сервер подтвердил размер и контрольную сумму | **да**, при нехватке места |
| `REC0007_P02_R.WAV` | часть восстановлена после пропадания питания; её метки — в `REC0007_P02.MRK` | нет |
| `REC0007_P02_R.SENT` | восстановленная часть подтверждена сервером | **да**, как и обычная `.SENT` |
| `REC0007_P03.BAD` | сбой записи | нет |
| `REC0007_P04.CONFLICT` | сервер ответил 409: у него другая часть с этим номером | нет |
| `REC0007_P05.REJECT` | сервер ответил 400 или 413 | нет |

Автоудаление трогает **только** `.SENT`, и только когда свободного места
меньше 1 ГиБ: старые первыми, пока не освободится 2 ГиБ. Не осталось
подтверждённых частей, а места всё равно мало — прошивка сигнализирует
ошибку и не удаляет ничего. Звук, который сервер не подтвердил, существует
в одном экземпляре, и молча его стирать нельзя.

Проверить карту целиком:

```bash
python tools/check_wav.py --dir E:/
```

## Что на плате есть, а чего нет

| Элемент | Состояние |
| --- | --- |
| Кнопка BOOT, GPIO0 | есть, используется как REC. Удержание при сбросе по-прежнему уводит в загрузчик |
| Кнопка RESET | есть, чисто аппаратная, из программы не читается |
| Светодиод пользователя, GPIO21 | есть, но это тот же пин, что CS карты. Пока карта смонтирована, использовать нельзя |
| Светодиод зарядки | есть, управляется микросхемой заряда, программе недоступен |
| Измерение заряда батареи | нет. Обычная Sense не имеет ни делителя, ни газометра |
| Отдельный LED состояния | нет, паять |
| Вибромотор | нет, паять |

`LED_BUILTIN = 21` проверено по `variants/XIAO_ESP32S3/pins_arduino.h` в ядре
esp32 3.3.11. Назначение кнопки BOOT на GPIO0 взято из документации Seeed и
**должно быть подтверждено на нашем экземпляре**.

Вибромотор нельзя подключать прямо к GPIO: нужен транзистор или MOSFET,
резистор в базу либо затвор и диод параллельно мотору. Пин из настройки
управляет ключом, а не мотором. Поэтому пины LED и вибро не зашиты в код, а
задаются после того, как плата окажется в руках:

```text
led_pin=1
vibro_pin=2
```

`-1` отключает канал. Пины карты, микрофона и кнопки прошивка занять не даст.

## Пины, которые считаем подтверждёнными

- PDM CLK: GPIO42
- PDM DATA: GPIO41
- microSD SCK: GPIO7
- microSD MISO: GPIO8
- microSD MOSI: GPIO9
- microSD CS: GPIO21 (общий с пользовательским LED)

В документации Seeed встречаются оба назначения CS — GPIO3 и GPIO21. Перебор
при старте убран намеренно: он маскировал ошибку монтирования под «другую
ревизию платы». Взят документированный GPIO21; если карта не поднимется,
`SD_CS_PIN` меняется по подтверждённой схеме, а не перебором.

## Управление через Serial

115200, команда вводится строкой и подтверждается Enter — иначе настройка
`server_url=...` сработала бы как команда `s`.

| Команда | Что делает |
| --- | --- |
| `r` | START в ARMED, STOP в RECORDING |
| `m` | метка (только во время записи) |
| `s` | состояние |
| `d` | диагностические счётчики |
| `l` | файлы на карте (не во время записи) |
| `c` | настройки отправки |
| `u` | отправить готовые части сейчас |
| `k` | очистка `.SENT` по порогу места |
| `p` | включить или выключить захват микрофона: для измерения тока в ARMED |

| `h` | справка |

Кнопка читается прерыванием, а не только опросом: TLS-рукопожатие блокирует
основной цикл на секунду-две, и короткое нажатие целиком уместилось бы внутри
этого окна. Прерывание запоминает фронты с их настоящим временем, цикл
разбирает их позже — нажатие не теряется и не превращается в длинное.
Потерянные фронты (если очередь всё же переполнится) видны в `d` как
`button_lost_edges`.

Счётчики по команде `d` — `captured_samples`, `written_samples`,
`dropped_samples`, `sd_write_max_ms`, `part_switch_max_ms`,
`buffer_high_watermark`, `upload_bytes`, `upload_duration_ms` — существуют
ради дня, когда приедет плата. Это средства измерения, а не показатели
продукта, и в интерфейс владельца они не идут.

## Отправка на сервер

Настраивается один раз, хранится в NVS, переживает перезагрузку. Пароль сети и
токен обратно не печатаются.

```text
wifi_ssid=HomeNet
wifi_pass=секрет
server_url=https://esp-recorder.duckdns.org:8443
device_token=токен
device_id=xiao-01
```

Wi-Fi выключен во время записи. После остановки устройство поднимает сеть,
отдаёт готовые части от старых к новым и гасит Wi-Fi. Сети нет — следующая
попытка через 1, затем 5, 15, 60 минут и далее каждый час; первая удачно
отданная часть сбрасывает расписание.

Передача прерываемая: нажатие REC обрывает её немедленно, потому что запись
важнее очереди. Недосланная часть уходит заново целиком — сервер идемпотентен
и дубликата не создаст.

Отказ по одной части не останавливает остальные. Останавливает только неверный
токен и нечитаемый адрес сервера — это про всё устройство сразу.

Время берётся по NTP только тогда, когда сеть уже поднята ради отправки. Ради
одних часов Wi-Fi не включается никогда.

Соединение только по HTTPS с проверкой сертификата. В прошивку вшит корневой
сертификат ISRG Root X1, он действует до 4 июня 2035 года; после этой даты его
нужно заменить в `Certificates.h`.

Полный контракт — в [shared/protocol.md](../shared/protocol.md). Приёмник и его
тесты — в [server/](../server/).

## Первое включение

Порядок шагов и список измерений — в
[docs/hardware-bring-up.md](../docs/hardware-bring-up.md). Коротко:

1. XIAO ESP32-S3 Sense с установленной платой Sense, камера не нужна;
2. microSD до 32 ГБ, FAT32;
3. кабель USB-C с передачей данных;
4. Arduino IDE 2.x, пакет плат `esp32` от Espressif 3.x, `PSRAM: OPI PSRAM`,
   Flash 8 MB;
5. Serial Monitor на 115200.

Ожидаемый вид первого запуска:

```text
[ring] 1048576 байт (PSRAM), предзапись 32.8 с
[sd] Ready. CS=GPIO21, card=... MB
[recover] No unfinished parts.
[sys] ARMED: микрофон слушает, буфер копит предзапись.

r
[rec] START session 0001 -> /REC0001_P01.TMP | предзапись 32.8 с
...
[rec] PART OK /REC0001_P01.WAV | ... | renamed=yes
[rec] STOP session 0001 | 1 parts | ... | marks 0 | dropped 0 samples
```

Если вместо этого будет что-то другое — это нормально: прошивка ни разу не
работала на железе. Важно не «чтобы совпало», а чтобы расхождение было видно
и объяснимо.
