# XIAO ESP32-S3 Sense Voice Recorder — firmware v0.2

Программный прототип компактного диктофона на **Seeed Studio XIAO ESP32-S3 Sense**.

Статус: на реальной плате не запускалось ни разу. Плата в пути. Всё ниже — то, что написано и собирается, а не то, что измерено.

## Что уже реализовано

- встроенный PDM-микрофон Sense;
- PCM 16 кГц / 16 бит / mono;
- потоковая запись WAV непосредственно на microSD;
- запись делится на части по 10 минут и группируется номером сессии;
- имена частей: `REC0007_P01.WAV` — сессия 7, часть 1;
- часть пишется как `.TMP` и получает имя `.WAV` только после чистого закрытия;
- восстановление незакрытых частей при старте: заголовок чинится по реальному размеру, файл получает суффикс `_R`;
- часть со сбоем записи переименовывается в `.BAD` и готовой не считается;
- микрофон включается на время записи и выключается после неё;
- управление через Serial Monitor;
- фиксированный `SD_CS` = GPIO21;
- запись включается встроенной кнопкой BOOT на GPIO0, паять ничего не нужно.

## Что на плате уже есть, а чего нет

| Элемент | Состояние |
| --- | --- |
| Кнопка BOOT, GPIO0 | есть, используется как REC. Удержание при сбросе по-прежнему уводит в загрузчик |
| Кнопка RESET | есть, чисто аппаратная, из программы не читается |
| Светодиод пользователя, GPIO21 | есть, но это тот же пин, что SD CS. Пока карта смонтирована, использовать нельзя |
| Светодиод зарядки | есть, управляется микросхемой заряда, программе недоступен |
| Измерение заряда батареи | нет. Обычная Sense не имеет ни делителя, ни газометра |

Отсюда список того, что действительно требует пайки: аккумулятор к контактам BAT на обратной стороне, измеритель заряда (делитель или модуль MAX17048) и отдельный светодиод состояния, если он нужен. Свободный вывод под светодиод — GPIO1 (D0).

`LED_BUILTIN = 21` проверено по `variants/XIAO_ESP32S3/pins_arduino.h` в ядре esp32 3.3.11. Назначение кнопки BOOT на GPIO0 взято из документации Seeed и должно быть подтверждено на нашем экземпляре.

## Как читать файлы на карте

| Имя | Что значит |
| --- | --- |
| `REC0007_P01.WAV` | готовая часть, можно забирать |
| `REC0007_P02_R.WAV` | часть восстановлена после пропадания питания |
| `REC0007_P03.TMP` | запись не закрыта, чинится при следующем старте |
| `REC0007_P03.BAD` | сбой записи, готовой не считается |

Забирать со стороны сервера следует только `*.WAV`. Проверить карту целиком:

```bash
python tools/check_wav.py --dir E:/
```

Потоковая запись выбрана специально: файл не хранится целиком в PSRAM. Это позволит позже писать длинные записи, ограниченные в основном ёмкостью карты памяти, а не оперативной памятью.

## Что понадобится, когда плата приедет

1. XIAO ESP32-S3 Sense с установленной Sense expansion board. Камеру можно не подключать.
2. microSD до 32 ГБ, FAT32.
3. USB-C кабель с передачей данных.
4. Антенна из комплекта понадобится позже для Wi-Fi/BLE; для первого офлайн-теста записи она не нужна.

## Рекомендуемая среда для самого первого запуска

Для первого hardware bring-up проще использовать **Arduino IDE 2.x**.

1. Установить пакет плат `esp32` от **Espressif Systems**, версия 3.x или новее.
2. Выбрать плату `XIAO_ESP32S3` / `XIAO ESP32S3 Sense` (название зависит от версии board package).
3. `Tools -> PSRAM -> OPI PSRAM`.
4. Flash: 8 MB.
5. Открыть `XiaoVoiceRecorder.ino` и прошить плату.
6. Открыть Serial Monitor на `115200`.

## Управление

В Serial Monitor. Команда вводится строкой и подтверждается Enter: иначе настройка `server_url=...` сработала бы как команда `s`.

- `r` — начать запись, повторно — остановить;
- `s` — статус;
- `l` — список файлов на microSD, во время записи запрещён;
- `c` — настройки отправки;
- `u` — отправить готовые части прямо сейчас;
- `h` — справка.

## Отправка на сервер

Настраивается один раз, хранится в NVS и переживает перезагрузку. Пароль сети и токен обратно не печатаются.

```text
wifi_ssid=HomeNet
wifi_pass=секрет
server_url=https://recorder.example.org
device_token=токен
device_id=xiao-01
```

Как работает цикл: Wi-Fi выключен во время записи. После остановки устройство поднимает сеть, отправляет все готовые `.WAV` от старых к новым и гасит Wi-Fi. Если сети нет — повтор через 5 минут. Доставленная часть переименовывается в `.SENT`, автоудаления нет.

Сервер подтверждает размер и контрольную сумму, и прошивка сверяет их со своими до того, как пометить часть доставленной. Повторная отправка той же части не создаёт дубликат: сервер отвечает `duplicate`.

Полный контракт — в [shared/protocol.md](../shared/protocol.md). Приёмник и его тесты — в [server/](../server/).

Соединение только по HTTPS с проверкой сертификата. В прошивку вшит корневой сертификат ISRG Root X1, он действует до 4 июня 2035 года; после этой даты его нужно заменить в `Certificates.h`.

Ожидаемый сценарий первого теста:

```text
[sd] Ready. CS=GPIO21, card=... MB
[recover] No unfinished parts.
[audio] Ready...

r
[rec] START session 0001 -> /REC0001_P01.TMP
...
r
[rec] PART OK /REC0001_P01.WAV | ... | renamed=yes
[rec] STOP session 0001 | 1 parts | ... 
```

После этого `REC0001_P01.WAV` можно открыть на компьютере обычным аудиоплеером.

## Почему SD_CS зафиксирован на GPIO21

В документации Seeed встречаются оба назначения — **GPIO3** и **GPIO21**. Перебор при старте убран: он маскировал ошибку монтирования под «другую ревизию платы» и мешал понять реальную причину отказа. Взят документированный GPIO21. Если на нашем экземпляре карта не поднимется, меняем `SD_CS_PIN` по подтверждённой схеме, а не перебором.

Тот же GPIO21 управляет пользовательским светодиодом. Пока карта смонтирована, мигать встроенным светодиодом независимо нельзя — для индикации нужен отдельный вывод.

## Пины, которые считаем подтверждёнными

- PDM CLK: GPIO42
- PDM DATA: GPIO41
- microSD SCK: GPIO7
- microSD MISO: GPIO8
- microSD MOSI: GPIO9
- microSD CS: GPIO21 (общий с пользовательским LED)

## Что НЕ входит в v0.1

Пока намеренно нет:

- Wi-Fi передачи файлов;
- BLE;
- мобильного интерфейса;
- контроля заряда батареи;
- deep sleep;
- VAD (автоматического обнаружения речи);
- шифрования записей;
- внешнего IM72D128;
- физической кнопки REC.

## План версий

### v0.1 — hardware bring-up
Микрофон -> WAV -> microSD. Управление через USB/Serial.

### v0.2 — автономный диктофон
Физическая REC-кнопка, индикация, безопасное завершение WAV, работа от Li-Po.

### v0.3 — передача на телефон
Включаем Wi-Fi только по запросу, локальная страница/REST для списка и скачивания записей.

### v0.4 — энергосбережение
Deep sleep, wake по кнопке, измерение реальной автономности.

### v0.5 — подготовка к приложению
Метаданные записей, API, удаление/скачивание, OTA.

После этого уже имеет смысл заниматься приложением телефона и AI-пайплайном транскрибации.
