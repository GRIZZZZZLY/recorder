# Сервер: приёмка, расшифровка, саммари, интерфейс

Личный сервер на одного владельца. Принимает части записей от диктофона, расшифровывает их через Deepgram, строит саммари через Claude Code и показывает результат в браузере iPhone.

## Из чего состоит

| `summarize.py` | Вызов `claude -p` с JSON-схемой |

## Память разговоров

Дизайн этапа 1 — в `docs/superpowers/specs/2026-09-12-memory-foundation-design.md`.

**Единая шкала времени.** Реплики хранятся в секундах от начала своей части, а показываются и отдаются модели в абсолютном времени сессии `Ч:ММ:СС`. Смещение части считается из размера файла, поэтому шкала не зависит от ошибок Deepgram. Сколько байт приходится на секунду — свойство самой части, а не всего проекта: при приёмке оно читается из заголовка WAV и хранится в `parts.bytes_per_second` (32 000 у моно с XIAO Sense, 64 000 у стерео с Recorder RevA). Иначе запись с двух микрофонов растянулась бы ровно вдвое, ничего при этом не уронив.

**Источник каждого вывода.** У решения, факта, задачи и вопроса без ответа модель обязана вернуть метку времени и дословную цитату. Сервер сверяет цитату с репликами рядом с этим временем. Совпала — кнопка «Послушать основание» ведёт на реплику. Не совпала — пункт остаётся, но помечен «источник не подтверждён». Выводы модели не удаляются молча.

**Поиск.** FTS5 по леммам: «сметы» найдёт «смету», «обсудили» найдёт «обсудить». Видовые пары вроде «обсудить / обсуждать» не сводятся — это задача поиска по смыслу в следующих этапах. Без `pymorphy3` поиск работает по точной форме слова.

**Говорящие.** Номера диаризации переименовываются внутри **части**, а не всей сессии: Deepgram обрабатывает каждую часть отдельным запросом, поэтому «говорящий 0» в первой части и «говорящий 0» во второй — разные номера, а не один человек. Флаг «это я» накапливает разметку для будущего определения своего голоса. Исходный транскрипт не меняется. Разметка, сделанная до этого разделения, при миграции размножилась на все части своей сессии — владелец видит то же, что видел раньше.

**Состояние обработки** на `/status`: очередь, ошибки, пропуски частей, расхождение длительности по файлу и по Deepgram, восстановленные части, части, которые не удалось сжать в архив, последняя выгрузка, минуты Deepgram.

## Архив: WAV в FLAC без потерь

Диктофон присылает PCM WAV — 115 МБ на час. Сервер после приёмки переводит часть в FLAC, который хранит тот же звук примерно вдвое компактнее.

Сжатие без потерь не объявляется, а доказывается: обе стороны декодируются обратно в PCM, и сравниваются контрольные суммы звука. Не сошлись — WAV остаётся, ошибка видна на странице состояния.

Порядок шагов выбран так, чтобы ни один сбой не оставил без записи:

1. кодируем во временный файл;
2. сверяем декодированный PCM;
3. подменяем файл одним действием;
4. записываем новый путь в базу;
5. и только теперь удаляем WAV.

Падение на любом шаге оставляет рабочую копию. Лишний WAV, оставшийся после падения в последней щели, убирается при следующем старте воркера.

Размер и контрольная сумма части в базе остаются от принятого WAV: это контракт приёмки, и по ним же считается шкала времени. Сжатие идёт после расшифровки и ничего не задерживает: приёмка о нём не знает вовсе.

Выключается переменной `RECORDER_ARCHIVE_FLAC=0`; уже сжатые части при этом продолжают работать.

Транскрипт хранится по частям, а не по сессии. Поздно пришедшая часть не заставляет переплачивать за уже расшифрованное. Саммари строится по сессии и помечается числом охваченных частей: пришла ещё одна — саммари пересобирается.

## Повседневная польза

Тезисы этапа 2 — в `docs/superpowers/specs/2026-09-12-stage2-daily-use-brief.md`.

**Задачи `/tasks`.** Задачи вынесены из саммари в таблицу `tasks`, потому что у них есть ручной статус, а саммари пересобирается после поздней части. `task_id` считается из нормализованных цитаты и текста, поэтому пересборка находит ту же строку и закрытие владельца не теряется. Задача, пропавшая из нового саммари, не удаляется, а помечается «исчезла из саммари». Фильтры: открытые, мои, просроченные, все. «Мои» — совпадение поля `owner` с именем говорящего, отмеченного «это я»; пока никто не отмечен, фильтр честно пуст.

**Сроки.** `duedate.py` разбирает «к пятнице», «в четверг вечером», «23 сентября», «завтра», «через неделю», «через 3 дня», «до конца месяца», «23.09» относительно дня разговора. День разговора пока равен дате выгрузки первой части: часы диктофона не синхронизированы. Неоднозначная фраза («как получится», «в сентябре», «до конца недели») датой не становится, а уходит в спорные места.

**Вопросы `/questions`.** Список читается из саммари всех сессий, в базе лежит только ручная пометка «ответ получен» или «снят». Автоматическое сопоставление с решениями следующих разговоров — этап 4.

**Проекты `/projects`, `/project/?name={имя}`.** Модель возвращает в саммари поле `topics` — одно-три названия тем, как они прозвучали. Таблица `project_aliases` сводит «Posiflora» и «Пози флора» в один проект. Лента идёт по дате разговора, а не по дате выгрузки.

**Спорные места `/review`.** Неподтверждённые источники, задачи без исполнителя, неразобранные сроки и числа, распознанные ниже порога уверенности. Уверенность слова (`c` в `transcripts.words`) начали сохранять здесь: у старых расшифровок её нет, и там ничего не помечается. Обработка ничего из этого не ждёт.

**Дайджест на `/`.** Главная страница фронтенда — не список записей, а сводка дня: сутки и неделя (минуты, разговоры, новые задачи, мои открытые, просроченные, вопросы, спорные места), под ней — мои открытые задачи и последние записи. Данные отдаёт `/api/ui/digest`, только запросы к базе, модель не вызывается. Доставка в Telegram — отдельным шагом. Список всех записей — на `/records`.

## Интерфейс

Фронтенд — отдельный проект в `web/` (Next.js, статический экспорт), сервер его не собирает. Сборка:

```bash
cd web
npm run build       # кладёт статику в web/out
```

`static_site.py` отдаёт `web/out` из каталога, заданного `RECORDER_WEB_DIR` (по умолчанию `web/out` рядом с `server/`), тем же паролем владельца, что и JSON-API. Если каталог не собран, `/` отвечает 503 с понятным текстом вместо мусора в браузере.

Страницы (десять `page.tsx` в `web/app`): `/` (сводка дня), `/records` (все записи), `/tasks`, `/questions`, `/projects` (список + псевдонимы), `/project/?name={имя}` (лента одного проекта), `/review`, `/status`, `/search`, `/session/?d={device_id}&n={session}`.

Старый серверный HTML-интерфейс (`web.py`, страницы владельца под `/legacy`) удалён в этой задаче: десять страниц нового фронтенда покрывают тот же функционал.

## Настройки

Обязательные:

```bash
RECORDER_DATA=/var/lib/recorder        # база и аудио
RECORDER_DEVICE_TOKEN=...              # токен диктофона, он же в прошивке
RECORDER_OWNER_PASSWORD=...            # пароль владельца для веб-интерфейса
DEEPGRAM_API_KEY=...
```

Необязательные:

```bash
RECORDER_OWNER_USER=owner
RECORDER_WEB_DIR=/opt/recorder/web/out # каталог собранного фронтенда
RECORDER_MAX_BYTES=67108864            # больше тела не принимаем
RECORDER_QUIET_MINUTES=12              # тишина, после которой сессия считается законченной
RECORDER_MIN_WORD_CONFIDENCE=0.7       # ниже этой уверенности число в факте считается спорным
RECORDER_ARCHIVE_FLAC=1                # 0 выключает перевод принятого WAV в FLAC
RECORDER_FLAC_LEVEL=8                  # уровень сжатия FLAC, считает сервер
RECORDER_FFMPEG=ffmpeg                 # путь к ffmpeg, если он не в PATH
RECORDER_STT=deepgram                  # движок распознавания; другой пока не написан
RECORDER_SUMMARY_MODEL=claude-opus-5
RECORDER_SUMMARY_TIMEOUT=900
RECORDER_CLAUDE_BIN=claude
CLAUDE_CODE_OAUTH_TOKEN=...            # долгоживущий токен, см. docs/step0-claude-headless-check.md
```

Пустой `RECORDER_OWNER_PASSWORD` закрывает интерфейс отказом 503, а не открывает его всем. Пустой `RECORDER_DEVICE_TOKEN` отклоняет любую загрузку.

`RECORDER_QUIET_MINUTES` должен быть больше интервала повтора у диктофона, иначе саммари уйдёт в работу посреди незаконченной выгрузки. Если прошивка прислала `X-Session-Parts` и все части пришли, саммари строится сразу, тишина не нужна.

Временный сбой расшифровки или саммари (сеть, 429, 5xx, таймаут) повторяется бесконечно с паузами 1, 5, 30, 120, 600 минут и далее раз в сутки. Навсегда закрывается только неисправимое: битое аудио, отсутствующий ключ. Первичная установка на VPS: `tools/vps-prepare.sh`, затем владелец запускает `tools/vps-finish-setup.sh` (спрашивает имя сайта в Duck DNS, ключ Deepgram и пароль, выпускает сертификат, включает nginx).

## systemd

Два юнита: приёмка и воркер. Воркер отдельно, потому что он может сутками ждать лимитов и не должен ронять приём файлов.

```ini
# /etc/systemd/system/recorder-api.service
[Unit]
Description=Recorder intake API
After=network.target

[Service]
User=zubr
WorkingDirectory=/opt/recorder/server
EnvironmentFile=/etc/recorder/recorder.env
ExecStart=/usr/bin/python3 -m uvicorn app:app --host 127.0.0.1 --port 8081
Restart=on-failure
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```ini
# /etc/systemd/system/recorder-worker.service
[Unit]
Description=Recorder transcription and summary worker
After=network.target recorder-api.service

[Service]
User=zubr
WorkingDirectory=/opt/recorder/server
EnvironmentFile=/etc/recorder/recorder.env
ExecStart=/usr/bin/python3 worker.py
Restart=always
RestartSec=30

[Install]
WantedBy=multi-user.target
```

Файл `/etc/recorder/recorder.env` содержит токены, права 0600 и владелец сервисного пользователя. В репозиторий он не попадает.

## nginx

Сайт диктофона: `https://esp-recorder.duckdns.org:8443` (имя заведено в Duck DNS 13 сентября 2026). Порт 443 на этом VPS занят маршрутизацией VPN по имени сервера, блок с `listen 443` не поднимается; остальные сайты сервера живут на 8443/8444/7443. Конфигурацию пишет `tools/vps-finish-setup.sh`, вот её суть:

```nginx
server {
    listen 8443 ssl;
    server_name esp-recorder.duckdns.org;

    ssl_certificate     /etc/letsencrypt/live/esp-recorder.duckdns.org/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/esp-recorder.duckdns.org/privkey.pem;

    # Часть записи весит около 19 МБ. Значение по умолчанию 1 МБ обрежет загрузку.
    client_max_body_size 64m;
    # Отдача 19 МБ с диктофона по домашнему Wi-Fi занимает десятки секунд.
    proxy_read_timeout 300s;
    proxy_request_buffering off;

    location / {
        proxy_pass http://127.0.0.1:8081;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
    }
}
```

Прошивка проверяет сертификат по вшитому корню ISRG Root X1, поэтому сертификат обязан быть от Let's Encrypt. Самоподписанный не подойдёт.

## Место на диске

Час записи занимает около 115 МБ в WAV. После перевода в FLAC — заметно меньше, но во сколько именно раз, зависит от самого звука: на тишине сжатие огромное, на шумной улице скромное. Настоящий коэффициент будет виден на записях с диктофона, и выдумывать его заранее незачем.

На VPS свободно 19 ГБ. Политика хранения на сервере по-прежнему нужна до того, как диктофон начнёт присылать записи ежедневно: автоудаления на сервере нет. На карте диктофона автоудаление появилось и трогает только подтверждённые сервером части.

## Незакрытые вопросы

Воспроизведение FLAC в Safari на iPhone владельца не проверено. Формат Safari поддерживает с одиннадцатой версии, но на устройстве владельца этого никто не открывал. Проверять так: зайти на сайт с телефона и включить любую запись, у которой на странице состояния архив уже сделан. Не играет — `RECORDER_ARCHIVE_FLAC=0` останавливает сжатие новых частей, а уже сжатые возвращаются в WAV из FLAC без потерь, потому что это и есть точная копия.

Тариф Deepgram требует сверки. План исходит из $0,0043 за минуту для Nova-3 на одном языке, но в одной из статей Deepgram встречается $0,0066 за минуту для готовых файлов. Разница почти в полтора раза, и от неё зависит, на сколько часов хватит $199.

Качество русской диаризации не проверялось. Номера говорящих — это метки, а не имена, и в шумной комнате на двадцать человек точность не обещана.

Расход лимитов на саммари не измерен. Расхождение в тарификации `claude -p` описано в `docs/step0-claude-headless-check.md` и тоже не закрыто.

Размер бандла фронтенда не измерен: вывод `npm run build` на Next.js 16.3.5 с Turbopack и `output: export` не печатает таблицу с колонкой First Load JS (в отличие от более старых версий Next.js) — только список статических маршрутов. Не выдумываю число; при необходимости размер надо смотреть по факту в `web/out/_next/static` после сборки.
