# Этап 2 «Повседневная польза» — тезисы для следующей сессии

Дата: 12 сентября 2026. Статус: реализован 12 сентября 2026 по прямому указанию владельца, без отдельного утверждения тезисов. Дизайн этапа 1 и его решения — в `2026-09-12-memory-foundation-design.md`.

## Что сделано и какие решения приняты по ходу

Сделаны все шесть пунктов состава: задачи `/tasks`, сроки (`server/duedate.py`), вопросы `/questions`, лента проекта `/projects` и `/project/{имя}`, спорные места `/review`, дайджест `/digest`. Описание — в `server/README_RU.md`, раздел «Повседневная польза». Проверок в `server/test_pipeline.py` стало 50 против 40.

Решения по открытым вопросам, принятые без владельца, чтобы не останавливать работу:

* «Мои» задачи считаются совпадением поля `owner` с именем говорящего, отмеченного «это я». Явного выбора «моя» в интерфейсе нет. Когда никто не отмечен, фильтр «Мои» показывает предупреждение, а не пустоту без объяснения. Отдельная ручная пометка добавляется за десяток строк, если совпадения по имени окажется мало.
* Фильтра по устройству нет: диктофон один, а фильтр по полю, у которого одно значение, — лишний элемент. Фильтр по сессии есть: `/tasks?session=7`.
* Порог уверенности для чисел — 0,7, вынесен в `RECORDER_MIN_WORD_CONFIDENCE`. На реальных записях его надо смотреть заново: сейчас он не проверен ни на одной живой расшифровке.

Отличие от тезисов: состояния вопросов хранятся отдельной таблицей `question_states`, а сам список вопросов читается из саммари на лету. Копия вопросов в базе не нужна — у них нет требования «исчезла из саммари», в отличие от задач.

## Что уже есть и на что опираемся

Единая шкала времени сессии, реплики с говорящими, саммари с полями `time` и `quote` у каждого пункта, проверка источника с флагом `confirmed`, список `open_questions`, имена говорящих и флаг «это я», поиск по леммам, страница состояния. Живой вызов модели дал 8 дословных цитат из 8.

## Состав этапа 2

### 1. Единые задачи

Таблица `tasks`, наполняемая из саммари: устройство, сессия, текст, исполнитель, срок как сказано, срок как дата, источник, статус `open | done | dismissed`, время закрытия. Страница `/tasks`: открытые по умолчанию, фильтры «мои», «просроченные», по сессии; галочка закрытия формой POST. «Мои» определяются через имя говорящего с флагом «это я» и совпадение с полем `owner`.

Ключевое требование: пересборка саммари после поздней части не должна терять ручной статус. Задача получает устойчивый идентификатор из нормализованных цитаты и текста; при пересборке новые пункты сопоставляются со старыми по нему, статус переносится. Несовпавшие старые задачи не удаляются, а помечаются «исчезла из саммари» для владельца.

### 2. Сроки

Разбор фразы срока относительно даты сессии: «пятница», «к пятнице», «в четверг вечером», «23 сентября», «завтра», «через неделю», «до конца месяца». Дата сессии пока равна времени выгрузки `parts.received_at`; настоящее время записи появится после синхронизации часов на диктофоне и потребует правки. Неоднозначный срок не превращается в дату, а попадает в спорные места. Просроченные подсвечиваются.

### 3. Вопросы без ответа

Уже в схеме. Страница `/questions` по всем сессиям с источником. Ручная пометка «ответ получен» или «снят». Автоматическое сопоставление с решениями следующих разговоров — этап 4, здесь не делаем.

### 4. Лента проекта

В схему саммари добавляется поле `topics`: 1–3 коротких названия проектов или тем разговора, как они прозвучали. Таблица псевдонимов владельца: «Пози флора» и «Posiflora» — один проект. Страница `/project/{имя}`: разговоры, решения, задачи, вопросы в порядке времени независимо от даты записи. Это же место для словаря имён и терминов, но в этапе 2 только псевдонимы проектов.

### 5. Спорные места

Страница `/review`: только то, что требует владельца. Пункты с неподтверждённым источником; задачи без исполнителя; срок, который не удалось разобрать; числа в фактах, у которых уверенность распознавания слов ниже порога — по колонке `transcripts.words`, там есть `confidence` у слова, его надо начать сохранять. Обработка ничего из этого не ждёт: спорное место — подсказка, не блокировка.

### 6. Дайджест

Страница `/digest` за день и за неделю: минут записано, сессий, новых задач, моих открытых задач, вопросов без ответа, спорных мест, ошибок обработки. Без ИИ, только запросы к базе. Доставка в Telegram — отдельным шагом после того, как страница устроит.

### 7. Отложено сознательно

«Вероятно выполнено» по следующему разговору — только как предложение, закрытие за владельцем; требует сопоставления текста, переносится на этап 4. Подготовка к встрече, история изменения решений, поиск по смыслу — этап 4. Речевые метрики — этап 3.

## Правки данных

Схема саммари: поле `topics`. Слова: сохранять `confidence`. Новые таблицы: `tasks`, `question_states`, `project_aliases`. Данных на сервере нет, миграции не нужны.

## Стоимость

Поле `topics` удлиняет запрос саммари и расходует лимиты подписки. Всё остальное — запросы к базе.

## Открытые вопросы к владельцу

Считать ли «мои» задачи по совпадению имени в `owner` с именем говорящего «это я», или добавить явный выбор «моя» в интерфейсе. Нужен ли фильтр по устройству, если диктофон один. Порог уверенности для чисел — начать с 0,7 и смотреть на реальных записях.
