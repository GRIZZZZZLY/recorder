# Ссылка на запись для другого человека

Дата: 8 октября 2026 · Ветка: `voice-recognition` (или новая от неё)

## Зачем

Владелец хочет показать одну запись другому человеку, не давая ему пароль от сайта.
Сейчас весь сайт, JSON-API и звук закрыты одним паролем владельца (`server/auth.py`),
чужого доступа нет совсем.

## Решения владельца

- Гость видит **звук, расшифровку и краткое изложение**. Только чтение: без задач
  владельца с их отметками, без кнопок правки, без других записей.
- Ссылка **живёт 7 дней**, владелец может **закрыть доступ раньше**.
- Страница гостя — **в дизайне сайта** («Студийный прибор»), с тем же плеером.
  Цена этого выбора: часть статики сайта отдаётся без пароля, поэтому список
  открытых адресов явный и проверяется тестом.

## Что открыто без пароля

Ровно эти адреса, списком разрешённого:

| Адрес | Что отдаёт |
|---|---|
| `/shared/` и файлы этой страницы в сборке (`shared/…`) | страницу гостя; ключ приходит в `?t=` |
| `/_next/…` | код и стили сборки; данных в них нет |
| `/icon.svg`, `/icon-192.png`, `/icon-512.png`, `/apple-touch-icon.png` | значки |
| `GET /api/share/{token}` | данные одной записи (поля ниже) |
| `GET /share/{token}/audio/{part}` | звук части этой записи, громкая копия как у владельца |

Всё остальное — `/`, `/records/`, `/session/`, `/api/ui/*`, `/audio/*`, `/api/v1/*` —
требует пароль, как сейчас.

Неизвестный, истёкший, закрытый ключ и ключ удалённой записи дают **один и тот же**
ответ 404 «ссылка не работает»: по ответу нельзя понять, что за ключом было.

Ответы гостевых адресов несут `Referrer-Policy: no-referrer` и
`X-Robots-Tag: noindex, nofollow`; JSON — ещё и `Cache-Control: no-store`.
Страница гостя ставит `<meta name="robots" content="noindex">` и
`<meta name="referrer" content="no-referrer">`.

## Сервер

### Хранение

Новая таблица в `server/db.py`:

```sql
CREATE TABLE IF NOT EXISTS shares (
    token      TEXT PRIMARY KEY,
    device_id  TEXT NOT NULL,
    session    INTEGER NOT NULL,
    created_at TEXT NOT NULL DEFAULT (datetime('now')),
    expires_at TEXT NOT NULL
);
```

- Ключ: `secrets.token_urlsafe(16)` — 22 знака, 128 бит. Хранится как есть:
  владельцу нужно снова скопировать живую ссылку. Утечка базы и так раскрывает
  все разговоры, хэш ключа тут ничего не защищает.
- Срок: константа `SHARE_DAYS = 7` в коде.
- `shares` добавляется в `SESSION_TABLES`: удаление записи стирает её ссылки.
- Закрыть доступ = удалить строку.
- Истёкшие строки не убираются фоном: их отсекает сравнение с `datetime('now')`
  при каждом запросе, и в список владельца они не попадают. Мусор — одна строка
  на выданную ссылку.

### Владельцу (под паролем, `server/api_ui.py`)

- `POST /api/ui/sessions/{device_id}/{session}/shares` → `{token, expires_at}`.
  404, если записи нет.
- `GET /api/ui/sessions/{device_id}/{session}/shares` → живые ссылки
  `[{token, created_at, expires_at}]`, новые сверху.
- `DELETE /api/ui/shares/{token}` → 200 `{"ok": true}`, как у удаления записи:
  `apiDelete` на сайте читает JSON из ответа. Повторное закрытие — тоже 200.

### Гостю (без пароля, новый модуль `server/share.py`)

`GET /api/share/{token}` собирает ответ **из разрешённых полей**, а не вычёркивает
лишние из ответа владельца: новое поле владельца само к гостю не попадёт.

Отдаётся:

- `day`, `first_at`;
- `parts`: `part`, `offset`, `seconds`, `envelope` — то, что нужно плееру;
- `summary`: `summary`, `topics`, `decisions`, `facts`, `tasks`, `open_questions`
  из готового изложения; `null`, если его нет;
- `timeline`: реплики (`part`, `idx`, `start`, `end`, `start_abs`, `speaker`,
  `label`, `text`);
- `speakers` (`part`, `speaker`, `name`, `auto`), `voice_groups`, `short_keys` —
  чтобы подписать реплики именами так же, как у владельца. `auto` нужен
  `groupRows` (`web/lib/speakers.ts`): имя, вписанное владельцем, побеждает
  догадку по голосу.

Не отдаётся: `device_id`, номер записи, отметки задач и вопросов владельца, метки
кнопкой, `is_me`/`me_name`, ошибки и статусы обработки, `received_at`,
размеры файлов, `recovered`, `failed_parts`. На странице гостя `is_me` подставляется
как `false`: на подписи реплик он не влияет.

Код, который сейчас строит части, реплики и голоса в `session_detail`, выносится в
общую функцию, чтобы владелец и гость считали одно и то же одним кодом.

`GET /share/{token}/audio/{part}` — та же отдача, что `/audio/…` в
`server/audio.py` (громкая копия, Range для Safari), но запись берётся из ключа.
Часть, которой у записи нет, — 404.

### Статика (`server/static_site.py`)

Перед проверкой пароля: если запрошенный путь после нормализации лежит под
`shared/` или `_next/` или это один из значков — отдать без пароля. Нормализация
та же `resolve()`, что уже отсекает выход из каталога сборки; список проверяется
по разрешённому пути относительно `WEB_DIR`, а не по сырой строке запроса, чтобы
`/shared/../records/` не прошёл.

## Сайт

### Страница записи владельца (`web/app/session/page.tsx`)

Блок «Поделиться»:

- кнопка «Создать ссылку» → полная ссылка `https://<хост>/shared/?t=<ключ>` и
  кнопка «Скопировать» (`navigator.clipboard.writeText`; если буфер недоступен,
  ссылка остаётся выделяемым текстом);
- список живых ссылок: «до 15 окт», «Скопировать», «Закрыть доступ».

### Страница гостя (`web/app/shared/page.tsx`)

- Шапка: тема и дата записи (`recordTitle`), без кнопки «назад».
- Тот же плеер: волна, скорость, переход между частями.
- Изложение и расшифровка, которая едет за звуком.
- Без меню разделов, без правки, удаления и формы имён.
- Свой `layout.tsx` с `robots: noindex`, `referrer: no-referrer` и `manifest: null`:
  манифест приложения владельца лежит под паролем.
- 404 → «Ссылка больше не работает. Попросите владельца прислать новую.»
  Ссылки на вход не показываются.

### Что меняется в общем коде

- `components/recorder/shell.tsx`: на `/shared` отдаёт страницу без меню и не
  запрашивает `/digest` — иначе гость получал бы 401 и ссылку на вход.
- `components/recorder/player.tsx`: необязательное свойство `audioBase`; по
  умолчанию — `/audio/{device}/{session}`, у гостя — `/share/{token}/audio`.
  `loadedPart` не меняется: со страницы гостя нет переходов внутри сайта, общий
  звуковой элемент на ней живёт с нуля.
- Расшифровка (`Transcript`, `Line`, `LevelMeter`) переезжает из
  `app/session/page.tsx` в `components/recorder/transcript.tsx`, чтобы обе страницы
  брали её из одного места.
- `lib/api.ts`: запрос гостевого JSON идёт мимо `/api/ui`.

## Проверка

Тесты сервера (`server/test_share.py`):

1. Владелец создаёт ссылку; гость по ней получает 200, и набор ключей ответа
   точно равен разрешённому списку (нет `tasks`, `questions`, `marks`, `device_id`).
2. Истёкшая, закрытая, неизвестная ссылка и ссылка удалённой записи — 404 с
   одинаковым телом.
3. Звук: своя часть — 200; номер части, которой у записи нет, — 404; ключ одной
   записи не отдаёт часть другой.
4. Без пароля: `/shared/` — 200, `/_next/static/…` — 200; `/`, `/records/`,
   `/session/`, `/shared/../records/`, `/api/ui/sessions`, `/audio/…` — вход или 401.
5. Создание, список и закрытие ссылок без пароля — 401.

Сайт: `npm run typecheck`, сборка, затем живая проверка на локальном сервере с
демо-данными в приватном окне — ссылка открывается и играет, остальные разделы
просят пароль, после «Закрыть доступ» ссылка гаснет.

## Вне рамок

- Скачивание файла гостем.

- Ссылка на отдельный кусок записи.
