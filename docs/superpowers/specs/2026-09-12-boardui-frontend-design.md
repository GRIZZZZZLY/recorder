# Новый фронтенд на BoardUI — дизайн

Дата: 12 сентября 2026. Статус: согласован с владельцем по секциям в этой же сессии, ждёт просмотра текста перед планом реализации. Предыдущие решения: `2026-09-12-memory-foundation-design.md` (этап 1), `2026-09-12-stage2-daily-use-brief.md` (этап 2).

## Зачем

Нынешний интерфейс владельца — HTML, который `server/web.py` собирает строками, с одним блоком CSS. Он работает, но выглядит как черновик. Владелец хочет интерфейс в духе референса Officevibe (редакторский тон, серифный курсив в заголовках, два синих: нави для веса и кобальт для действия), только в тёмной теме, и на готовых компонентах BoardUI.

## Решения владельца, принятые в этой сессии

| Вопрос | Решение |
| --- | --- |
| Формат | Новый фронтенд на BoardUI, а не перекраска `web.py` и не макеты |
| Развёртка | Статика внутри FastAPI: Node только на машине сборки, на VPS ничего нового |
| Сборка | Next.js 16, `output: 'export'`, BoardUI без правок. Vite отклонён из-за правок блоков BoardUI |
| Главная | Сводка дня, записи отдельным пунктом меню |
| Тема | Только тёмная, переключателя нет |

## Что такое BoardUI и что из него берём

BoardUI — React 19 + Tailwind CSS v4 + React Aria Components, ставится исходниками в проект (`npx boardui@latest init`, затем `add <имя>`), лицензия MIT. Свободный каталог — 62 элемента: базовые компоненты (кнопки, бейджи, поля, табы, таблица на TanStack), блоки приложения (боковая панель, каркас, пустые состояния), токены и типографика. Платные компоненты Pro не используем.

Правила BoardUI для кода (`AGENTS.md` в их репозитории) принимаем как свои: цвета только семантическими токенами, типографика только составными утилитами, классы через `cx()`, иконки из `@remixicon/react`.

Из блока `app-shell` берём только `dashboard-sidebar`: сам `app-shell` жёстко зашит под их стартер (чат, дашборд, `STARTER_SITE_PREFIX`). Свой каркас пишется на 60–80 строк поверх боковой панели, их файл не правится.

## 1. Структура и сборка

```
Recorder_v0_1/
  web/                      Next.js 16 + TypeScript + Tailwind v4, BoardUI как исходники
    app/                    страницы: / (сводка), records, session, search, tasks,
                            questions, projects, project, review, status
    components/base/…       поставлено BoardUI
    components/application/ dashboard-sidebar и другие блоки BoardUI
    components/recorder/    наши блоки: карточка сессии, реплика, пункт саммари с источником,
                            нижний плеер, каркас страницы
    styles/                 globals.css, theme.css с тёмными значениями, typography.css
    lib/api.ts              клиент JSON-API и типы ответов
  server/
    api_ui.py               JSON-роуты для фронта, тонкие обёртки над db.*
    web.py                  старые HTML-страницы: на время миграции под /legacy, затем удаляются
```

Настройки Next: `output: 'export'`, `trailingSlash: true`, `images.unoptimized: true`. В `app/layout.tsx` на `<html>` стоит класс `dark` без условий; переключателя темы нет.

Сборка идёт на машине владельца: `cd web && npm run build` даёт `web/out/`. Этот каталог — артефакт, а не исходник; на VPS он попадает вместе с кодом, Node на VPS не нужен.

FastAPI отдаёт `web/out` catch-all маршрутом `GET /{path:path}` под `Depends(owner)`: тот же Basic-пароль на статику и на API, включая `_next/static`. Каталог задаётся переменной `RECORDER_WEB_DIR`, по умолчанию `../web/out` относительно `server/`. Правила отдачи: путь без расширения — `index.html` из соответствующего каталога (`/session/` → `session/index.html`); файла нет — `404.html` из сборки; каталога сборки нет — `/` отвечает 503 «фронтенд не собран», `/legacy` продолжает работать.

Статический экспорт не умеет динамических сегментов пути без перечисления значений при сборке, поэтому страницы с параметрами используют строку запроса: `/session/?d=xiao-01&n=7`, `/project/?name=…`, `/search/?q=…`, `/tasks/?show=mine&session=7`. Для одного владельца форма адреса не важна.

Разработка: `next dev` на порту 3000 с `rewrites` для `/api/*` и `/audio/*` на `http://127.0.0.1:8099`. Экспорт эти правила игнорирует, в режиме разработки они работают, и заголовок Basic проходит через прокси.

Аутентификация не меняется: Basic поверх HTTPS, как сейчас. Браузер запрашивает пароль при первой загрузке документа и дальше сам добавляет заголовок ко всем запросам того же origin, включая `fetch`. Если API отвечает 401 (пароль сменили), фронт показывает баннер «нужен вход заново, обновите страницу», а не пустой экран.

## 2. JSON-API

Префикс `/api/ui/`, чтобы не смешивать с `/api/v1/upload` для диктофона. Каждый роут — 5–15 строк: вызов существующей функции из `db.py`, даты в ISO 8601, ошибки JSON-ом с кодом 404. Логика не дублируется: всё, что сейчас считает `web.py`, уже лежит в `db.py`.

| Роут | Отдаёт |
| --- | --- |
| `GET /api/ui/digest` | `db.digest(1)`, `db.digest(7)`, мои открытые задачи, пять последних сессий, число спорных мест |
| `GET /api/ui/sessions` | список сессий: устройство, номер, дата, длительность, частей всего и расшифровано, состояние саммари |
| `GET /api/ui/sessions/{d}/{n}` | части с признаком «восстановлена» и ошибкой расшифровки, саммари, таймлайн реплик на абсолютной шкале, провалившиеся части, имена говорящих, задачи сессии со статусом, пометки вопросов |
| `POST /api/ui/sessions/{d}/{n}/speakers` | тело `{"names": {"0": "Игорь"}, "me": 0}`; `me: null` — «меня нет» |
| `GET /api/ui/search?q=` | попадания по сессиям; текст реплики отдаётся сегментами `[{text, hit}]`, подсветку считает сервер по леммам, HTML не отдаётся |
| `GET /api/ui/tasks?show=&session=` | `db.task_rows` с признаками «моя», «просрочена», «исчезла»; флаг «никто не отмечен как я» |
| `POST /api/ui/tasks/{d}/{n}/{id}` | тело `{"status": "done" \| "dismissed" \| "open"}` |
| `GET /api/ui/questions?show=` | `db.question_rows` |
| `POST /api/ui/questions/{d}/{n}/{id}` | тело `{"state": "answered" \| "dropped" \| "open"}` |
| `GET /api/ui/projects` | проекты с числом разговоров и датой последнего, таблица псевдонимов |
| `GET /api/ui/projects/{name}` | лента проекта по дате разговора |
| `POST /api/ui/projects/aliases` | тело `{"alias": "posiflora", "canonical": "Пози флора"}` |
| `GET /api/ui/review` | `db.review_items` |
| `GET /api/ui/status` | `db.processing_status` |

Аудио остаётся на `GET /audio/{d}/{n}/{p}` через `FileResponse`: он отдаёт Range, без которого Safari на iPhone не играет.

Формы и параметр `back` из `web.py` уходят: состояние живёт на клиенте, действия идут `fetch`-ом.

## 3. Экраны и навигация

Каркас: боковая панель BoardUI на десктопе, выдвижная панель на iPhone. Пункты: Сводка, Записи, Задачи, Вопросы, Проекты, Спорные, Поиск, Состояние. У «Задач» бейдж с числом моих открытых задач, у «Спорных» — с числом пунктов. Язык интерфейса русский.

**Сводка `/`.** Надзаголовок «ДИКТОФОН · 12 СЕНТЯБРЯ». Заголовок-дисплей собирается из чисел дня: «Три разговора, две задачи и одно *спорное место*», курсивная фраза — последний элемент перечисления. Ряд плиток сутки/неделя: минуты записи, разговоры, новые задачи, спорные места. Ниже две колонки: «Мои открытые задачи» с действием «Закрыть» и «Последние записи». Если никто не отмечен «это я», плитка моих задач говорит об этом прямо.

**Записи `/records`.** Карточки сессий: дата, длительность, частей всего и расшифровано, чип состояния «обрабатывается» или «готово». Свежие первыми.

**Сессия `/session/?d=&n=`.** Надзаголовок «СЕССИЯ 0007 · 12 СЕНТЯБРЯ · 4 МИН», темы как пилюли-ссылки на проект, пересказ. Списки Решения, Факты, Задачи, Вопросы: время табличными цифрами, текст, точка состояния источника (подтверждён, не подтверждён, не найден) и призрачная кнопка «Послушать». У задач — статус и действие «Закрыть» на месте. Блок говорящих: строка на говорящего — номер, поле имени, радио «это я», плюс «меня нет». Транскрипт по частям, активная реплика подсвечена; часть с провалившейся расшифровкой показана предупреждением на своём месте. Плеер закреплён снизу по центру страницы — там, где в референсе живёт чат-виджет: текущая часть, время, пауза; клик по реплике или по «Послушать» перематывает и запускает нужную часть. На телефоне плеер во всю ширину, на десктопе около 360px.

**Поиск `/search/?q=`.** Поле-пилюля, результаты сгруппированы по сессиям, совпавшие слова выделены `mark`, клик ведёт на реплику в сессии.

**Задачи `/tasks/`.** Фильтры BoardUI `button-group`: Открытые, Мои, Просроченные, Все; параметр `session` сужает до одной сессии. Строки-карточки, не таблица: текст задачи многострочный, на телефоне таблица ломается. Метаданные: исполнитель или «не назван», срок как сказано и разобранная дата или «дату не разобрали», сессия. Чипы «моя», «просрочено», «исчезла из саммари». Действия «Закрыть», «Снять», «Вернуть» призрачными кнопками.

**Вопросы `/questions/`.** Тот же паттерн: фильтры «Без ответа» и «Все», действия «Ответ получен», «Снять», «Вернуть».

**Проекты `/projects/`, `/project/?name=`.** Сетка карточек проектов с числом разговоров и датой последнего; форма псевдонима из двух полей и кнопки. Лента проекта: дата серифом, пересказ, под ним решения, задачи и вопросы разговора. Порядок — по дате разговора.

**Спорные `/review/`.** Группы по виду с бейджами-счётчиками; у пункта чип вида, текст, деталь, ссылка на реплику. Подпись сверху: обработка ничего из этого не ждёт.

**Состояние `/status/`.** Плитки: очередь расшифровки, очередь саммари, минуты Deepgram. Таблицы BoardUI `data-table`: последняя выгрузка, части с ошибкой, саммари с ошибкой, пропуски частей, расхождение длительности, восстановленные части.

Общее поведение: загрузка показывается скелетонами BoardUI; пустые состояния — честный текст, например «Пока пусто: тема появится после следующих записей»; действия меняют строку оптимистично, ошибка откатывает и показывает тост; транскрипт и саммари — чужой текст из распознавания, вставляется только как текст React, без `dangerouslySetInnerHTML`.

## 4. Визуальная система

Референс светлый, нужен тёмный. Двухсиний принцип сохраняется: нави — вес, кобальт — действие. Значения переопределяются в `styles/theme.css` в блоке `.dark`, компоненты BoardUI подхватывают их через семантические токены.

| Токен BoardUI | Значение | Основание |
| --- | --- | --- |
| `background-full` (канвас) | `#080e33` | Ink Navy углублённый: сам `#0c1754` слишком светлый для сплошного фона |
| `background-primary` (карточки) | `#0c1754` | Ink Navy: «тёмная карточка» референса становится нормой |
| `background-secondary` (ховер, вложенные блоки) | `#132070` | ступень выше карточки |
| `text-primary` | `#ffffff` | Paper White |
| `text-secondary` | `#eaebf8` | Lavender Mist |
| `text-tertiary` | лаванда с непрозрачностью 60% | вспомогательные подписи |
| `separator-border`, `border-button-default`, `border-table` | `rgba(240, 233, 225, 0.14)` | кремовая линия референса как тёплый полупрозрачный волос, не холодный серый |
| `accent-500` | `#2545ff` | Electric Cobalt: кнопки действия, активный пункт меню, фокус-кольцо. Контраст с белым текстом около 6:1 |
| `accent-400`, `accent-600` | `#3d5aff`, `#1c37d9` | ховер и нажатие |
| точки состояния источника | зелёная, янтарная, коралловая `#ff6b5c` | подтверждён, не подтверждён, не найден; «просрочено» — коралл в тексте, без заливок |
| `mark` | фон лаванда, текст нави | подсветка поиска |

Кобальт нигде не используется для текста, рамок и больших заливок — только для действия и фокуса.

Шрифты — все с кириллицей, иначе русский интерфейс развалится. Подключаются через `next/font/google`: файлы скачиваются при сборке и отдаются с нашего сервера, браузер к Google не обращается. `next/font` проверяет субсет `cyrillic` при сборке и падает, если его нет.

| Роль | Шрифт | Как используется |
| --- | --- | --- |
| Дисплей | Literata 400 и italic | замена Martinaplantijn; H1 каждой страницы с курсивной фразой; 40px на телефоне, 48px на десктопе, интерлиньяж 1.1 |
| Подзаголовки, eyebrow | Inter Tight 500 | трекинг −0.02em на 24–32px; eyebrow 12px верхним регистром с трекингом 0.12em |
| Текст, кнопки, таблицы | Inter | стандарт BoardUI; время и числа `tabular-nums` |

Форма: карточки и поля — радиус 16px, пилюли — 100px, изображений нет. Кнопки без теней: цвет и есть высота. Единственная тень — у нижнего плеера, `0 8px 32px rgba(0, 0, 0, 0.4)`. Расстояния по сетке 8px, отступ карточки 24px на телефоне и 32px на десктопе, ширина контента до 1200px. Плитки сводки на телефоне в две колонки, цели касания не меньше 44px.

Что не делаем: чат-виджет референса — до этапа 4 у проекта нет вопросов к записям, а пустой композер противоречит правилу владельца не обещать лишнего; его место на экране сессии занял плеер. Светлой темы нет. Иллюстраций и стоковых картинок нет. Третьего цвета заголовков нет.

## 5. Проверки

Python: `pytest` на `api_ui.py` — каждый роут отдаёт ожидаемый JSON на тех же фикстурах, что и сейчас; тесты HTML-страниц переезжают в тесты API. Отдельные проверки отдачи статики: catch-all отдаёт `index.html`, `/session/?d=…` отдаёт `session/index.html`, каталога сборки нет — 503, `_next/static` без пароля — 401.

Фронт: `tsc --noEmit` и `next build` как обязательные проверки перед приёмкой шага. Сборка падает на ошибках типов и на отсутствующем субсете кириллицы у шрифта.

Playwright не заводим: одному владельцу дешевле смотреть глазами. Приёмка каждого экрана — живой сервер на 127.0.0.1:8099 с демо-данными из `tools/seed_demo.py`, как в этой сессии.

## 6. Порядок миграции

Старый интерфейс живёт до конца миграции, ничего не ломается посередине.

1. Проверка `output: 'export'` на Next 16 пустым проектом — до всего остального. Если экспорт сломан, включается запасной путь Б (Vite + React Router), согласованный с владельцем как резерв.
2. Каркас: `web/` с BoardUI, тёмная тема, шрифты, боковая панель с пустыми страницами. FastAPI отдаёт `web/out`, старые страницы переезжают под `/legacy` (одна строка `include_router(..., prefix="/legacy")`).
3. Экраны по одному, каждый со своим роутом API и приёмкой на живом сервере: сводка → записи → сессия с плеером → задачи → вопросы → спорные → проекты → поиск → состояние.
4. Паритет достигнут — рендер из `web.py` и его тесты удаляются, `server/README_RU.md` переписывается под новую структуру.

## 7. Развёртка

Репозитория git у проекта нет, на VPS код и так едет `rsync`-ом. Скрипт `tools/deploy.sh` делает `npm run build` в `web/` и `rsync` каталогов `server/`, `shared/`, `web/out/` на `config1` в `/opt/recorder/`. В `/etc/recorder/recorder.env` добавляется `RECORDER_WEB_DIR=/opt/recorder/web/out`. systemd-юниты и nginx не меняются: тот же процесс `uvicorn` на 8081 отдаёт и API, и статику.

## Риски и что измеряется, а не обещается

- Статический экспорт в Next 16 проверен 12 сентября 2026 на пустом проекте: next 16.3.5,
  react 19.2.8, tailwindcss 4.3.3, BoardUI и `useSearchParams` собираются в статику.
  `useSearchParams` требует обёртки `Suspense`, иначе сборка падает. `boardui init` не
  подключает свои стили сам — импорт в `app/layout.tsx` меняется вручную.
- Размер бандла на iPhone через сотовую сеть — измеряется после первой сборки.
- Контраст пар цветов — проверяется на собранных страницах, заявленное «около 6:1» для кобальта с белым посчитано по формуле WCAG, на экране не смотрелось.
- Кириллица в Literata и Inter Tight — подтверждается сборкой, а не памятью.
