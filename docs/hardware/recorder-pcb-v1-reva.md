# Recorder PCB V1 RevA

Своя плата под финальный носимый диктофон: XIAO ESP32-S3 без платы расширения
Sense, два цифровых микрофона, кнопка, вибромотор, светодиод, измерение заряда.
Production package (`Recorder_PCB_V1_RevA_PRODUCTION_PACKAGE`: Gerber, Drill,
BOM, CPL) передан производителю; производитель собирает SMD сам, владелец
ставит XIAO и подключает аккумулятор.

**Состояние на 18 сентября 2026: плата в производстве, в руках её нет.**
Всё ниже — проектные решения и то, что прошивка про них знает. Ни одно из них
не проверено на железе.

## Что решено и не меняется

| Параметр | Значение |
| --- | --- |
| Размер | 62 × 22 мм |
| Толщина | 0,8 мм |
| Слоёв | 2 |
| Контроллер | XIAO ESP32-S3, устанавливается на плату |
| Аккумулятор | Li-Po ≈300 мА·ч, 40 × 13 × 5 мм, к BAT XIAO; заряд — встроенной схемой XIAO |
| Микрофоны | 2 × Infineon IM72D128V01XTMA1, PDM, bottom-port |
| Вибромотор | через MOSFET AO3400A с резистором в затвор и защитным диодом |

### Микрофоны

Два PDM-микрофона на одной паре линий: общий CLK, общая DATA. Один микрофон
`SELECT → GND`, другой `SELECT → 3V3`: каждый выдаёт данные в своём полупериоде
CLK, приёмник раскладывает их по слотам L и R. Это штатная схема для пары PDM
MEMS, и PDM RX ESP32-S3 её поддерживает аппаратно.

- на каждой ветке DATA — последовательный резистор ≈100 Ω;
- у каждого микрофона 100 нФ + 1 мкФ по VDD, как можно ближе к корпусу;
- акустическое отверстие в PCB Ø0,8 мм NPTH под bottom-port;
- канал от корпуса к MEMS — как можно короче; в корпусе — акустически
  прозрачная защитная сетка;
- вибромотор не рядом с MEMS.

### Распиновка

| Сигнал | GPIO | В прошивке (`BoardConfig.h`, профиль `reva`) |
| --- | :-: | --- |
| Battery ADC | 1 | `BAT_ADC_PIN`, ADC1_CH0, не конфликтует с Wi-Fi |
| REC / MARK | 2 | `REC_BUTTON_PIN`, `INPUT_PULLUP`, читается прерыванием |
| Vibro (затвор MOSFET) | 3 | `VIBRO_PIN` |
| Status LED | 4 | `LED_PIN` |
| PDM CLK | 5 | `PDM_CLK_PIN` |
| PDM DATA | 6 | `PDM_DATA_PIN` |
| microSD SCK | 7 | `SD_SCK_PIN` |
| microSD MISO | 8 | `SD_MISO_PIN` |
| microSD MOSI | 9 | `SD_MOSI_PIN` |
| microSD CS | 44 | `SD_CS_PIN` |

Формат звука на RevA: 16 кГц / 16 бит / **стерео**, 64 000 байт в секунду,
часть 10 минут = 38 400 000 байт PCM (на Sense — моно, вдвое меньше).

Прошивка под RevA собирается уже сейчас, `bash tools/build.sh --board reva`,
и помечает себя `hardware unverified`. Что именно она предполагает и чего не
знает — в разделе «Что подтвердить по плате в руках».

## ECO-01: небольшие улучшения, если производство ещё позволяет

После сравнения RevA с документацией Infineon и Espressif и разбором чужих
плат оказалось, что основные решения уже верные. Предлагаемые правки — не
исправление ошибок, а удобство первого запуска с осциллографом.

**Существующая RevA не считается ошибочной. Производство из-за этого списка
отменять или останавливать не нужно.** Если платы уже запущены — пусть едут
как есть; если ещё нет — попросить внести ECO-01.

### Контрольные точки

Добавить площадки:

- `TP_PDM_CLK` — общий CLK;
- `TP_PDM_DATA` — общая DATA после резисторов;
- `TP_MIC_3V3` — питание микрофонов;
- `TP_GND`.

Очень желательно ещё две: `MIC1_DATA` и `MIC2_DATA` **до** своих 100-омных
резисторов. Если первый прототип даст шум вместо речи, по ним за минуту видно,
какой из двух микрофонов молчит или мешает соседу.

### Footprint резистора в линии CLK

```text
XIAO GPIO5 ── R_CLK ── общий PDM CLK
              0 Ω
```

По умолчанию ставится 0 Ω, то есть поведение платы не меняется. Footprint
нужен на случай ringing/overshoot на реальной плате: тогда подбирается
небольшой последовательный резистор без новой ревизии PCB.

### Фильтр на входе Battery ADC

```text
BAT+
 │
делитель
 │
 ├──── GPIO1
 │
100 нФ
 │
GND
```

Если конденсатора после делителя ещё нет — добавить ≈100 нФ на землю. АЦП
ESP32-S3 шумный; Espressif рекомендует развязку на входе и усреднение
нескольких чтений. Прошивка усредняет 16 чтений (`cfg::BATTERY_SAMPLES`), но
конденсатор дешевле программного усреднения.

### Что писать производителю

Если платы ещё не запущены: «будет небольшое обновление RevA.1 / ECO-01 —
контрольные точки, опциональный `R_CLK 0R` в линии CLK, проверить наличие
100 нФ на BAT_ADC». Если запущены — ничего не останавливать.

## Что подтвердить по плате в руках

Прошивка про RevA знает только то, что записано в `BoardConfig.h`. Перед
первым включением сверить с реальной платой:

1. **Коэффициент делителя батареи.** В прошивке `BAT_DIVIDER = 2.0` (два
   равных резистора, 4,2 В → 2,1 В). Это предположение, не значение из BOM.
   Неверный коэффициент даст неверное напряжение и процент — поправить одно
   число в `BoardConfig.h`.
2. **Порядок каналов.** Какой микрофон `SELECT → GND`, тот и левый слот; если
   на плате наоборот — это не ошибка, а факт для документации: сервер и
   пост-обработка каналы не различают.
3. **Кнопка на GPIO2.** Подтяжка внутренняя (`INPUT_PULLUP`); проверить, что
   нажатие даёт LOW и нет дребезга длиннее 40 мс.
4. **CS карты на GPIO44.** Если карта не монтируется — сверить со схемой, а не
   перебирать пины.
5. **Ток вибромотора через AO3400A** и отсутствие наводок на микрофоны при
   вибрации.

## Кривая заряда

Процент в `X-Battery` считается по типовой кривой разряда Li-Po
(`Battery.h`, `percentFromMillivolts`): 4,20 В → 100 %, 3,80 В → 45 %,
3,60 В → 8 %, 3,30 В → 0 %. Это ориентир до первого измерения разряда нашего
аккумулятора под нашей нагрузкой; точки таблицы заменяются измеренными.
Линейная формула отвергнута: на плоском участке 3,7–3,9 В, где аккумулятор
проводит большую часть жизни, она врёт на десятки процентов.

## Стерео и сервер

Сервер принимает WAV любого числа каналов: ffmpeg переводит его в FLAC без
потерь, Deepgram сводит стерео в один поток. Но длительность части сервер
сейчас оценивает по размеру файла с моно-константой 32 000 байт/с
(`server/db.py`, `BYTES_PER_SECOND`). Для стерео это даст удвоенную длину на
ленте дня. Поправить до первой отправки с RevA — либо читать число каналов из
заголовка WAV при приёмке, либо передавать его заголовком. Сервер намеренно не
трогается заранее: пока с него отправляет только моно-прототип.
