- Headless-режим `claude -p` и Claude Agent SDK официально поддерживаются с подпиской Team.
- Долгоживущий токен: команда `claude setup-token` на машине с браузером (ПК пользователя) выдаёт токен `sk-ant-oat01-...` сроком около года; на сервере он передаётся через переменную `CLAUDE_CODE_OAUTH_TOKEN`. Device-code вход по SSH без браузера не реализован.

- Глобальный `~/.claude/settings.json` на VPS задаёт модель `claude-fable-5[1m]`. Для воркера саммари модель передавать явно через `--model`.

## Рекомендуемая схема модуля саммари

Не эмулировать консоль (tmux, expect, вставка промпта). Воркер очереди вызывает `claude -p` как обычный процесс: один вызов на одну запись, без инструментов, ответ строго по JSON-схеме.

```bash
timeout 600 claude -p \
  --tools "" \
  --max-turns 3 \
  --no-session-persistence \
  --model claude-opus-5 \
  --output-format json \
  --json-schema "$(cat shared/summary.schema.json)" \
  --system-prompt "$(cat server/prompts/summary_ru.txt)" \
  < transcript_123.txt > result_123.json
```

Воркер: Python-скрипт под systemd, читает SQLite-очередь (status = transcribed), запускает команду выше через `subprocess.run`, проверяет код выхода и поле `is_error`, сохраняет `structured_output` в запись, переводит статус в done. Ошибки: таймаут и 5xx — повтор с паузой; строка `authentication_error` в stderr или debug-логе — очередь ставится на паузу, уведомление владельцу, транскрипт остаётся доступным.

Фрагмент systemd-юнита:

```ini
[Service]
User=zubr
EnvironmentFile=/etc/recorder/claude.env   # CLAUDE_CODE_OAUTH_TOKEN=sk-ant-oat01-..., права 0600
ExecStart=/usr/bin/python3 /opt/recorder/server/worker.py
Restart=on-failure
RestartSec=30
```

Важно: структурированный ответ по `--json-schema` Claude Code формирует внутренним вызовом инструмента, это отдельный ход. С `--max-turns 1` вызов завершается `subtype: error_max_turns` и `structured_output: null`. Ставить `--max-turns` не меньше 2, в команде выше 3 с запасом.

## Сроки жизни токенов (измерено 12 сентября 2026)

Прочитаны поля `~/.claude/.credentials.json` на VPS, секреты не извлекались. Часовой пояс сервера Europe/Moscow, ниже время в UTC.

| Токен | Выдан | Истекает | Срок |
| --- | --- | --- | --- |
| accessToken | 11.09 21:26 | 12.09 05:26 | ровно 8 часов |
| refreshToken | 11.09 20:40 | 09.10 20:40 | ровно 28 суток |

Ключевой вывод: срок refresh-токена абсолютный, а не скользящий. В 21:26 произошло обновление access-токена, файл был перезаписан, но `refreshTokenExpiresAt` остался прежним, 20:40. То есть обновление access-токена не продлевает refresh-токен. Вывод сделан по одному наблюдению, но он объясняет отказ: вход был 19 июля, примерно 16 августа refresh-токен умер, дальше все вызовы получали 400 на обновление и 401 на запрос.

Практическое следствие: вход через claude.ai по SSH требует ручного повторного входа каждые 28 суток независимо от активности. Для беспилотного воркера не годится.

Дополнительно в файле: `scopes` включает `user:inference` и `user:sessions:claude_code`, `subscriptionType` team, `rateLimitTier` default_claude_max_5x.

Срок токена от `claude setup-token` проверить не удалось. Он выдаётся только на машине с браузером, у меня её нет, а в готовом токене срок не читается офлайн. Заявленный год взят из вторичных источников и официально не подтверждён. Токен относится к тому же классу `sk-ant-oat01`, что и восьмичасовой access-токен, отличается только сроком, поэтому проверять надо фактом.

Порядок проверки после создания токена: записать дату создания в `docs/`, поставить ежедневную cron-проверку здоровья и считать реальный срок по дате первого отказа.

```bash
# /opt/recorder/scripts/claude_health.sh — ежедневно по cron
set -a; . /etc/recorder/claude.env; set +a
out=$(timeout 120 claude -p --tools "" --max-turns 2 --no-session-persistence \
      --model claude-opus-5 --output-format json "Ответь одним словом: ok" 2>&1)
echo "$out" | grep -q '"subtype":"success"' || {
  echo "$(date -Is) claude auth health FAILED" >> /var/log/recorder/auth.log
  # сюда же уведомление владельцу
}
```

## Запасной вариант

Прямой API-ключ Anthropic и пакет `anthropic` из Python без Claude Code. Плюсы: нет истечения OAuth, нет 11 повторов, обычный SDK. Минус: оплата за токены. Ориентир по публичным тарифам Opus 5 ($5 / $25 за 1M токенов): час русской речи ≈ 25–35 тыс. входных токенов, саммари ≈ 2 тыс. выходных, итого около $0,20 за час аудио. Оценка, не проверка счёта.

## Действия пользователя

1. На своём ПК выполнить `claude setup-token`, скопировать токен в `/etc/recorder/claude.env` на VPS (права 0600). Не хранить токен в репозитории.
2. Обновить Claude Code на VPS: `claude update` или native installer с https://code.claude.com/docs/en/setup (npm-установка объявлена устаревшей).
3. Проверить текущую редакцию статьи о тарификации Agent SDK и настройки администратора Team.
4. Повторить тестовый вызов из этого документа. При успехе этап 0 по части AI закрыт.
