# Recorder — правила проекта

## Проверки и пуш в master

- CI нет: GitHub Actions убраны 12 октября 2026. Единственный барьер перед
  `master` — `bash tools/check.sh`.
- Перед каждым пушем в `master` прогнать `bash tools/check.sh` целиком и
  пушить только при зелёном итоге. Красный — чинить, а не пропускать шаг и не
  пушить «пока так».
- Не возвращать GitHub Actions и не подключать другой внешний CI без прямой
  просьбы владельца.

## Какие тесты писать

- В первую очередь — интеграционные тесты сервера: настоящее приложение через
  HTTP API (`TestClient`) или настоящий воркер с временной базой и файлами,
  проверка того, что увидит владелец.
- E2E — только короткие и простые, только для критических сценариев.
- Юнит-тесты — минимум: только чистая логика, ошибка в которой тихо портит
  записи или данные владельца, и только если интеграционный тест до неё не
  достаёт. Прошивка — исключение по форме: её логика проверяется на хосте
  (`XiaoVoiceRecorder/host_tests`), но тоже целыми сценариями (запись, сбой
  питания, восстановление), а не по функции.
- Не писать тесты на формулировки промптов и журнала, на приватные помощники,
  на порядок внутренних вызовов; не дублировать то, что уже покрыто.

## Окружение владельца

- `g++` и `ffmpeg` на Windows нет: `tools/check.sh` сам отправляет хост-тесты
  прошивки и серверные тесты на VPS (`ssh config1`), рабочие каталоги сервера
  при этом не трогаются.
- arduino-cli и ядро esp32 лежат на `E:/arduino-toolchain` (`tools/build.sh`
  находит их сам). Плата — COM5.
- ESP-IDF 5.5.5 с инструментами — в `E:/esp-idf` (с 15 окт 2026). Собирать и
  шить только через `bash tools/idf.sh` (`build`, `-p COM5 flash`): `idf.py` из
  Git Bash напрямую не работает.

## Прошивка: Arduino и ESP-IDF

- Плата с 12 октября 2026 работает на сборке ESP-IDF (`firmware/`): только в
  ней буфер отправки TCP 32 КиБ. Arduino-сборка — тот же код, быстрая проверка
  и откат.
- `tools/check.sh` собирает IDF через `tools/idf.sh`; если ESP-IDF на машине
  нет, шаг пропущен и это видно в итоге. Образ IDF для платы шить только
  собранный из того же кода, что уходит в `master`.
- Версия Arduino-ядра для IDF закреплена (`==3.3.12` + `dependencies.lock`):
  менять её только вместе с прогоном на плате.
